# Changelog

All notable changes to the **`@reticlehq/*`** packages are documented here (each entry notes the package it affects). The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

## [2.3.0] — 2026-08-05

Desktop release: Electron and Tauri are supported surfaces with a committed battery behind them rather than a hand-run number in the docs, and CI compiles the Rust for the first time. Also a feedback channel so an agent can report a bad verdict, a round of false-green fixes found by driving the desktop apps by hand, and an honesty pass on which frameworks we actually claim to support. No breaking API changes; on-disk flow files stay version 1.

### Behaviour changes — read these before upgrading

Nine changes alter what an existing caller gets back. Seven change RESULTS rather than names, so nothing fails to compile; one is a pure rename, and it is a rename of analytics event names rather than of anything in the API; the last narrows which frameworks we claim to support.

- **Unknown tool parameters are now REFUSED, not ignored.** Pass a key a tool does not declare and the call fails with that tool's own valid example, instead of the key being silently dropped. This is the one change that can break a working script, and it is worth it: `reticle_clock` with a misspelled parameter used to return `{"frozen":false}` — a well-formed NEGATIVE that reads as a fact about the app, when it meant "you named the parameter wrong". Silently ignoring input was never a documented contract, and it made every tool a false-negative generator for one typo.
- **The bridge SAMPLES above its message-rate cap instead of disconnecting.** A burst used to close the socket permanently (a policy code the SDK never retries), leaving the app running and Reticle blind. Events above the cap are now dropped and reported as a `rate-limited` blind spot, so a verdict over a sampled window says `coverage: partial`. Raise `RETICLE_MAX_MESSAGES_PER_SECOND` for a legitimately busy app.
- **`reticle_project` and `reticle_domain` cap their output** (25 by default) and report `totalRuns` / `flowsTruncated`. `project` was returning the entire run history — 176 runs and ~5,000 tokens on this repo, growing with every run.
- **`reticle_network_mock` and `reticle_viewport` return `no-cdp-provider`**, not `no-visual-provider`. Nothing outside this repo matched the old code; if you gate on the reason string, update it.
- **`reticle_network { ok }` now filters.** It was accepted-and-ignored, so `{ ok: false }` returned calls that had SUCCEEDED. If any script leaned on that shape, it was getting a superset; it now gets what it asked for. A still-pending call matches neither `true` nor `false`.
- **DESKTOP VISUAL BASELINES MUST BE RE-TAKEN.** Reticle's own presenter panel and annotator button used to be composited into every desktop screenshot; they are now hidden for the shot. Existing baselines therefore contain UI the fresh capture will not, and the first `reticle_visual_diff` against one will report a large, real-looking change that is entirely the observer leaving the frame. Delete the affected files in `.reticle/visual/` and re-capture.
- **A one-way Electron `ipcRenderer.send` now appears in `reticle_network`**, where nothing appeared before. It carries `oneWay: true` and NO `ok`/`status`, because the renderer cannot learn the outcome — so a filter counting IPC calls will see more of them, and an `{ ok }` filter still will not claim them either way.

- **EVERY TELEMETRY EVENT WAS RENAMED, AND THE PER-TOOL-CALL EVENT IS GONE.** This changes nothing for users of Reticle — it is opt-out anonymous metrics either way — but it breaks every existing analytics chart. Old names (`install`, `invoke`, `session_start`, `session_end`, `tool`, `feedback`) stop being emitted; the new taxonomy is listed in [`docs/telemetry.md`](docs/telemetry.md). Charts that must span the change need both names, or a filter on the event-version property `v` (now `3`). `invoke` in particular is not comparable to `cli_command_run` even after renaming, because `invoke` double-counted every daemon spawn.

- **`SKILL.md` no longer offers Vue, Svelte or SvelteKit, and now offers Astro.** Those three were on the framework list users pick from with no app and no CI gate behind any of them — the SDK is framework-agnostic and all three may well work, but nothing proved it and nothing would have reported it breaking. If you picked one of them, pick "Plain HTML / vanilla" instead; the wiring is the same `connect()` call. Astro moves the other way: it had an app and an integration gate the whole time and was never offered, so it is on the list now, alongside Remix. `reticle init` still wires SvelteKit — that path is real and is the only one that can register a session there — but the plan now opens with an UNVERIFIED step saying so, instead of emitting wiring that reads as a support claim. (`SKILL.md`, `@reticlehq/server`)

### Known limitation

`reticle-tauri`'s **Windows** capture path compiles and is type-checked against the real WebView2 API, but has never been executed on Windows. It ships labelled rather than withheld so it can be tried — treat a green from it as unconfirmed until someone reports otherwise.

### Added

- **`reticle mcp` and `reticle serve` no longer count themselves twice.** Both start the daemon by re-running the `reticle` binary, and that child re-entered the CLI entry point and emitted its own `invoke` event — so one human action produced two. The inflation was not uniform, which is what made it dangerous: agent-driven sessions double-counted while one-shot commands like `version` counted once, skewing the RATIO between commands and not merely the scale. The daemon's lifecycle was already reported by its own events; a spawned daemon is not a CLI run. (`@reticlehq/server`)
- **The telemetry event names now say what happened.** `invoke` sounded like "a tool was invoked" but meant "the CLI binary ran", while the event that actually meant a tool call was `tool`, emitted from a file called `invoke-tool.ts` — confusing enough that it confused its own authors. The taxonomy is now `reticle_installed`, `cli_command_run`, `daemon_started`, `daemon_stopped`, `verification_completed`, `project_profiled`, `version_changed`, `runtime_crashed`, `feedback_submitted`. **This forks the analytics series**: post-upgrade events land under new names, so a chart spanning the change needs both, or a filter on the `v` property (now `3`). (`@reticlehq/core`, `@reticlehq/server`)
- **Tool usage is aggregated instead of streamed — ~100x fewer events.** A single agent verification loop is 50–200 tool calls, and one event per call meant the analytics bill scaled with how hard people used the product. Tool calls are now counted in memory and leave once, inside `daemon_stopped`, as a histogram (`{"reticle_act": 40, "reticle_assert": 12}`). That is also strictly more informative: the histogram preserves the SHAPE of a session, where 52 separate rows only said that 52 things happened. Counting is free on the hot path — no network, no promise, nothing to fail during a tool call. (`@reticlehq/server`)
- **`verification_completed` — the product's own thesis, as a metric.** Every verdict now reports whether the assertion passed AND whether Reticle refused to call it verified. That second flag is `falseGreenCaught`: a green that Reticle caught lying, which is the number worth reporting rather than "tools were called". Emitted from the one chokepoint every verification tool already crosses, so all four are covered and a fifth is covered the moment it joins the set. (`@reticlehq/server`)
- **`project_profiled` — activation, not just activity.** Once per daemon start: framework and major version, a size bucket, monorepo or not, project age in whole weeks, how many saved flows/baselines/runs/capsules exist, and which feature families are in use, reduced to a single `featureDepth` fraction. A DAU chart cannot tell forty saved flows with visual baselines from two snapshot calls; this can. (`@reticlehq/server`)
- **`runtime_crashed` and error analytics, without collecting anything anyone wrote.** Errors and crashes are grouped by a **fingerprint** — the message with every variable part (ids, paths, numbers, quoted strings) stripped, then hashed — so the same defect from a thousand machines collapses into one rankable row while no flow name, path, or message is ever sent. Crash stacks keep only Reticle's own frames, reduced to `basename:line`; frames from your application are dropped entirely. (`@reticlehq/server`)
- **`version_changed`.** `reticle update` and `reticle rollback` now report from → to and which direction. A rollback is a release-quality alarm — someone was hurt enough by a release to go backwards — and it was previously invisible. (`@reticlehq/server`)
- **One repo now counts as one project.** `projectId` hashes the **git origin** (normalized, so `git@github.com:Acme/Web.git` and `https://github.com/acme/web` agree) instead of the directory path. The contract in `@reticlehq/core` always said "hash of the git remote (or cwd)", but the implementation only ever hashed the path — so one repo cloned by four teammates counted as four projects, which made team adoption look like unrelated individuals. Still one-way; the URL itself never leaves the machine. (`@reticlehq/server`)
- **Every event says whether a human or an agent caused it.** A typed `reticle` command is a person; an MCP tool call is the agent. Deliberately NOT inferred any finer than that — whether you asked your agent to verify or it decided on its own lives in a prompt Reticle never sees, and guessing would put something in a dashboard that nobody could later tell apart from a measurement. (`@reticlehq/core`, `@reticlehq/server`)
- **`reticle identify` — opt-in, and the only way Reticle ever learns who you are.** The product question is real (which anonymous ids are companies who would pay for support or an enterprise licence?) and the tempting answer — infer it from a git remote, an email in `git config`, an npm org — is the wrong one. It would contradict a promise made in four places, break the legal basis the telemetry policy states, and be worse at the job: a scraped lead is a cold email from a tool the recipient trusted, which is how an advocate becomes someone who runs `reticle telemetry disable` and tells their team to. So this is a command a human types, with `--context company|side_project|open_source|learning` and optional `--company`/`--email`. It prints what it will send first, including the non-obvious part — that identifying yourself links the anonymous history already recorded from that machine — and `reticle identify --forget` undoes it. Nothing is inferred, ever. (`@reticlehq/server`, `@reticlehq/core`)
- **Agents can now ASK for things, not only report failures.** Reticle is built for agents, which makes the agent the user whose wishes should decide the roadmap — and the one user who was never asked. It would hit a limitation, work around it, finish the task, and the wish would evaporate with its context window. `reticle_feedback` gains `feature_request` (something that does not exist) and `improvement` (something that exists but costs too many calls), kept separate because the responses differ completely. Alongside the request it captures `need` (the GOAL — "I need to know the page stopped changing", not "add a waitForIdle tool", which is a guess at the solution), `impact`, and `currentApproach` — the workaround, usually the most useful field in the report, because it proves the need is real and often reveals a cheaper fix than the feature being asked for. The tool description and the `reticle init` agent rule now actively invite requests rather than only failures. (`@reticlehq/core`, `@reticlehq/server`)
- **The agent self-reports its MODEL.** MCP's `clientInfo` carries a client name, title and version and has no concept of a model, so the transport genuinely cannot tell us — the agent can, and the report is already something it authored. It changes how a request is read: a limitation that blocks a smaller model is often a docs problem, while the same one from a frontier model means the surface is genuinely short. The client's `version` is now captured too, so "cursor 0.42 specifically" is answerable. (`@reticlehq/core`, `@reticlehq/server`)
- **Redaction is now derived from the input, not a list of field names.** It named `text` and `trace` explicitly, so the three new structured fields bypassed it entirely and would have gone to the wire raw — a `currentApproach` reading "hardcoding the token sk-…" would have shipped the token. Enumerating the fields to protect is the same class of mistake as hand-copying an enum: correct the day it is written, quietly wrong at the next addition. One derived list now drives both redaction and assembly, so a sixth field is covered the moment it exists. (`@reticlehq/server`)
- **A telemetry CONTRACT, enforced by a test rather than by memory.** Telemetry fails silently — nothing throws, no test reddens, the data is simply and permanently absent — which makes "remember to instrument it" an unworkable rule. `telemetry-contract.test.ts` now fails when a tool that produces a verdict is missing from `VERIFICATION_TOOLS`, when a finding kind stops being counted as a bug, when an event name reads as an object rather than something that happened, or when a vocabulary is hand-copied instead of derived from core. [`docs/telemetry-contract.md`](docs/telemetry-contract.md) is the human-facing version, and `CLAUDE.md` now names telemetry as part of a feature rather than a follow-up. The guard was mutation-tested: adding a thirteenth contradiction kind to core makes it fail with the exact remedy in the message. (`@reticlehq/server`)
- **CI-found bugs were not counted at all.** `reticle verify` and the HTTP verify surface do not go through `runTool`, so the entire runner path emitted nothing — no timing, no `verification_completed`, and no `bug_found`. Every defect Reticle caught in CI was invisible to the one number we intend to publish, on precisely the surface most likely to run at scale and unattended. `telemetry/run-telemetry.ts` reports from the assembled run artifact, so it cannot double-count. (`@reticlehq/server`)
- **`bug-found.ts` hand-copied core's contradiction vocabulary.** Correct on the day it was written, and silently wrong the moment a thirteenth kind was added: the new kind would have been counted as an ordinary single-channel fault, quietly deflating the false-green number. It now derives from `ContradictionKind`. A copied enum is a drift hazard anywhere; it is a correctness hazard when the thing that drifts is a public claim. (`@reticlehq/server`)
- **`falseGreen` is now defined by presentation, not by assertion.** It read "the app's own assertion PASSED and Reticle refused it", which is only how the defect arrives through `reticle_assert` — through `reticle_crawl` there is no assertion at all and the UI simply moves on over a failed write. Both are the thing a human watching the screen cannot see, and that is what the flag has to mean for the number to be publishable. (`@reticlehq/core`)
- **`bug_found` — the number that says whether Reticle works.** Every other metric measures whether Reticle is USED; this measures whether it finds anything, and it is the only one that can honestly be published or shown to an investor because it counts outcomes for users rather than activity by them. Built on the classification that already existed: twelve contradiction kinds, three crawl anomaly kinds, flow regressions, and failed assertions. Deliberately discrete events rather than only a counter, because the distribution is the argument — "we found 4,000 bugs" is a claim, "1,200 of them were greens that lied, a passing assertion sitting on a failed write that no screenshot and no human watching the screen would have caught" is evidence. Counted conservatively: a defect a contradiction already explains is not also counted as a failed assertion, and crawl's single-channel faults are never inflated into false greens. Kinds only — never a selector, a URL, or any description of the app it was found in. (`@reticlehq/core`, `@reticlehq/server`)
- **A `sessionId` on every event.** Nothing tied `daemon_started` → the verifications → a crash → `daemon_stopped` into one story: events could only be grouped by machine and approximate time, so "what was happening when this crashed?" was unanswerable, and three concurrent daemons on one machine (which the product explicitly supports) interleaved into one undifferentiated stream. It is also sent as PostHog's own `$session_id`, which lights up its built-in session views and funnels rather than requiring custom queries. Held in memory and never written to disk — a restarted daemon is genuinely a new session, so this adds no durable identifier. It cannot be backfilled, which is why it was worth adding before the data mattered. The dead `sessionMs` and `tool` fields, which nothing had set since the v3 rename, are gone. (`@reticlehq/core`, `@reticlehq/server`)
- **Browser-leg latency is measured separately from tool time.** A four-second `reticle_act` used to be unattributable — our overhead, or the app taking four seconds to settle, with no way to tell and opposite fixes. `browserMs` against `busyMs` separates "Reticle is slow" from "their app is slow". (`@reticlehq/server`)
- **Tool timing, machine state, and connection FAILURES.** Three things that were simply absent. Every tool call is now timed — total and worst-case per tool, plus a `busyMs` total that answers "how much time does verification actually cost" and a peak-concurrency count. A machine snapshot (our process memory, free/total RAM, load average, CPU count) is taken at session end and on every crash, because "your machine ran out of memory" and "Reticle has a bug" produce identical-looking failures and were previously indistinguishable. And browser/lease connections now record **attempts, successes and classified failure causes** (`chromium_missing`, `cdp_unreachable`, `browser_crashed`, `pool_timeout`) — the previous counter recorded only successes, and recorded them inconsistently, incrementing before the await on the CDP path and after it on the launch path, so one number meant attempts, the others meant successes, and nothing in the data said which. A connection metric that cannot express failure misses the only question worth asking. (`@reticlehq/core`, `@reticlehq/server`)
- **`mcp_client_connected` and `init_completed` — the two ends of the funnel.** A daemon can sit up for days with no agent ever attaching, which looks like healthy adoption in every existing metric and is in fact an onboarding failure nobody reports; `mcp_client_connected` separates "running" from "being used", and its `reconnect` flag separates transport churn from enthusiasm. `init_completed` instruments setup, which had none at all — a run that died on a missing dependency was indistinguishable from someone who never tried, and those two have completely different fixes. Failures are classified (`no_package_json`, `dependency_install`, `mcp_registration`) rather than sent as raw errors. (`@reticlehq/core`, `@reticlehq/server`)
- **The in-page half of Reticle can finally report its own failures — and no longer takes the SDK down with it.** Half the product runs inside the browser and had no error reporting whatsoever: every `catch` in the SDK swallows by design (correctly — instrumentation must never break the app it observes), so an observer that threw on page load simply made the product quieter and nobody found out. Worse, the observer list was built bare, so ONE `install*` that threw aborted the whole `connect()` and the app got no instrumentation at all. Each install is now guarded: the healthy observers still run, and the failure is reported over the bridge the SDK is **already** connected to — it makes no outbound request of its own, so "the SDK only talks to localhost" stays exactly true, and the daemon decides what goes onward. Failures arrive as a new `sdk.failed` event, are fingerprinted and variable-stripped like tool errors, and ride out in `daemon_stopped` as `sdkErrors` — deliberately a separate bucket, since a broken observer and a failing tool call are different defects with different owners. (`@reticlehq/browser`, `@reticlehq/core`, `@reticlehq/server`)
- **Crash and error reports are now diagnosable, not merely rankable.** The first version sent a fingerprint and nothing else, which meant you could see that forty machines hit `a3f2c1d8e9b0` and had no way on earth to learn what `a3f2c1d8e9b0` was — a group key with no dictionary. Reports now carry the four things a root-cause analysis needs: **where** (Reticle's own stack frames as `resolveAnchor@act-tools.js:142` — function, file and line), **what** (the message with every quoted string, path, URL, id and number replaced by `*`), **when** (the MCP tool in flight), and **what the agent was attempting** (the preceding tool names — `snapshot → act → act → assert` is a verification loop; `lease_acquire → navigate → crash` is a startup problem). Plus the Node version and CPU architecture, which crashes cluster hard by and which we were not recording at all. Session errors gained the same treatment: `errorKinds` was an opaque `{hash: count}` map and is now an `errors` array carrying the stripped message and the tool that produced each shape. Frames belonging to the user's application, and their paths, are dropped before any of this is built. (`@reticlehq/core`, `@reticlehq/server`)
- **Reticle now tells the agent when a new version exists.** Nothing checked before this: `checkForUpdate` had exactly one caller — the `reticle update` command — so a published release was invisible to every install until a human happened to type it, which in practice meant never. A fix could ship and sit unused for months on the machines hitting the bug it fixed. The daemon now checks npm in the background (cached 24h on disk, best-effort, silent when offline) and rides the answer out on the next tool result as `update_available`, alongside the session-health and pool-lease nudges. It deliberately does NOT self-install: swapping the binary under a running session restarts the daemon and drops every agent attached to it, mid-work the human never agreed to interrupt. The envelope carries the version numbers and the exact command; `reticle init`'s agent rule tells the agent to relay it and to run the update between tasks rather than mid-verification. (`@reticlehq/server`)
- **The human feedback prompt re-arms instead of firing once.** Strictly-once was too fragile: a daemon lives for days, the ask landed on the very first verification — often hours before the human could answer — and if the agent did not relay it in that turn the signal went to zero for the rest of the process with nothing to tell us. It now re-offers after another 25 verifications, capped at three asks per daemon ever. A tool that pesters gets muted, and a muted tool collects nothing — the same outcome as never asking, reached more annoyingly. (`@reticlehq/server`)
- **`telemetry-events-test` — every event fired for real and checked on the wire.** Added to the e2e battery because of a bug the unit tests could not have caught: `daemon_stopped`, the event carrying a whole session, was emitted fire-and-forget microseconds before `process.exit(0)`, so the POST was killed every time and the event NEVER arrived. Nothing threw, no assertion failed — the only way to see it was to stand up a real endpoint and notice nothing landed. The spec drives the real built modules against a real capture server (real network, real process semantics, real redaction), covers all ten event kinds, and needs no browser and none of the battery's three servers, which makes it the cheapest and most reliable spec in the suite. Half its checks are leak checks: every payload that could carry a secret, a password, a customer email, or a home directory is asserted NOT to. Both halves were mutation-tested — reintroducing the fire-and-forget emit fails 9 checks, disabling redaction fails 3 — so the guards are known to bite rather than assumed to. (`apps/e2e`)
- **The user/project graph is now countable.** Distinct users, projects per user, and **users per project** all fall out of `anonymousId` × `projectId` — but the third only became real once `projectId` started hashing the git origin, and it is only trustworthy when there _was_ an origin to hash. So every event now carries `projectIdSource` (`git_origin` | `cwd`): an unpushed repo has nothing shared to fingerprint, so those rows always show exactly one user, and left unlabelled they would drag the team-adoption average toward 1 and hide the very thing being measured. `project_profiled` additionally reports `git` (`none` | `local_only` | `remote`) and the forge (`github`/`gitlab`/`bitbucket`/`azure`/`sourcehut`/`codeberg`/`self_hosted`). Self-hosted repos report **only** `self_hosted` — never the hostname, because a private git host is usually `git.<company>.com` and sending it would identify the company outright. (`@reticlehq/core`, `@reticlehq/server`)
- **Which flags and parameters people actually use — names only.** `cli_command_run` reports the flags PRESENT on the invocation, and `daemon_stopped` reports parameter usage per tool (`{"reticle_act": {"ref": 40, "action:click": 31}}`). The names come from vocabularies we wrote; the VALUES never leave, and for CLI flags that rule is absolute — `--http-token` holds a secret, `--drive` a URL, `--storage-state` a path. Tool parameters have one narrow exception: an explicit allowlist of parameters whose values are enums we defined, where anything unrecognized reports as `other` so a future schema change cannot quietly start forwarding free text. `reticle_act`'s `args` — the text typed into the app, a password on a login form — is deliberately not on it. (`@reticlehq/core`, `@reticlehq/server`)
- **A feedback channel — Reticle can finally hear when it is wrong.** Reticle is built for agents, and until now the agent was the one party who knew a verification had gone wrong and had no way to say so: it would hit a tool that misbehaved, work around it, and that knowledge died at the end of the turn. Two paths now close the loop. **`reticle_feedback`** lets an agent file a report the moment a Reticle tool returns something wrong, unobservable, or undecidable — the three are distinct `kind`s (`bug` / `gap` / `ambiguity`) because "our defect", "our blind spot" and "our verdict was unusable" are different work items, and collapsing them into "it didn't work" destroys the only signal that says what to build next. The tool asks for a root-cause analysis and the call trace, not a complaint. **`reticle feedback [--rating 1-5] [--bug] "…"`** is the human half: one command, no prompts, no editor, no account. Each report carries detected context — framework and its major version, `web`/`electron`/`tauri` runtime, `blink`/`gecko`/`webkit` engine, CDP-vs-SDK driver, the MCP client's own name, user-vs-project scope, and the Reticle version — which is what turns "reticle_act misses the click" into a bug that names its own conditions. (`@reticlehq/server`, `@reticlehq/core`, `@reticlehq/browser`)
- **Reticle now asks — at the two moments worth asking.** An **unrecognized** tool error (one with no known recovery hint, i.e. the case most likely to be a defect in Reticle rather than in your app) now carries a request for an RCA; a recognized error still carries its recovery hint and nothing else, so the agent always gets exactly one next move. Separately, the first **verification** that completes in a session carries a one-shot prompt asking the agent to check in with the human about how it went. Once per process, never repeated, and silent whenever the feedback channel is switched off — asking for feedback we have been told not to collect is worse than not asking. (`@reticlehq/server`)
- **`RETICLE_FEEDBACK=0`.** Free-text feedback is a different privacy class from anonymous counters, so it gets its own switch: keep the adoption metrics, never send prose. Feedback is also **never passive** — no code path emits it without an explicit call carrying content someone authored — and is **redacted client-side** before the wire (emails, URL credentials, `Authorization`/api-key values, `sk-`/`ghp_`/`AKIA`/`xoxb-`/JWT tokens, home-directory paths). `reticle feedback` prints the exact payload before sending and names every redaction rule that fired. Every existing opt-out (`reticle telemetry disable`, `RETICLE_TELEMETRY=0`, `DO_NOT_TRACK`) disables it too, and [`docs/telemetry.md`](docs/telemetry.md) documents the whole contract. (`@reticlehq/server`, `@reticlehq/core`)
- **The SDK reports its rendering engine** (`blink` / `gecko` / `webkit`) alongside the runtime it already reported in each health heartbeat — a coarse three-value bucket, never the user-agent string. It rides the existing `PAGE_HEALTH` payload, so no wire change was needed. (`@reticlehq/browser`, `@reticlehq/server`)
- **`apps/atlas` — a fixture built to be hard rather than to be passed.** Every other app in `apps/` is a few hundred lines with defects planted in shapes the detector already looks for; `bench-shop`, `demo` and `example-react` are empty directories. Atlas is 10,000 shipments behind a server that reconciles asynchronously and sometimes reverts what it accepted, an SSE stream mutating rows nobody clicked, a virtualized table where ~29 of 10,000 rows exist in the DOM, idempotency keys that make a double-submit look like two successes, bulk endpoints that return 200 with per-item failures inside the body, and per-endpoint latency so orderings differ run to run. Its README states the rule it is built on: **defects are not planted to match Reticle's detectors** — they are emergent (written the way a team under deadline writes it) or taxonomy-derived and recorded by DRIVING the app, never by listing what was typed in. It found a false green on its first drive. (`@reticlehq/atlas`)

- **Reticle now sees the files your app GENERATES.** A CSV export never crosses the network — the app builds a Blob, hands it to `URL.createObjectURL`, and clicks an anchor — so there is no request for an outside-the-browser tool to intercept, and Playwright MCP has no tool that returns a downloaded file at all. Reticle runs INSIDE the page, where the Blob is constructed. A `download` event now carries `{ filename, mimeType, bytes, lines }`, plus a capped, redacted `preview` when body capture is on. The LINE COUNT is reported regardless, because it is a number rather than customer data and it is the whole tell for "25 rows in a file the toast calls 128". Measured on a real merchant dashboard, one Export click surfaced three defects at once that every other channel called a clean success: `filename: "transactions-128-rows.csv"` with `lines: 26`, a header reading `amount_inr` over rows denominated in USD, and a row containing the unquoted `3 Aug, 10:00 pm` that shifts every column after it. The benchmark's ground truth records all three as missed by BOTH toolchains, for one reason: nobody opened the file. (`@reticlehq/browser`, `@reticlehq/core`)

- **The store adapters are now tested against the real libraries, not against fakes of them.** `store-adapters.test.ts` drives hand-written fakes shaped like each library's surface, and those are not useless — breaking an adapter alone fails them, measured rather than assumed. What a fake structurally cannot catch is drift between the fake and the LIBRARY, because the fake IS the belief under test: if Jotai renamed `sub` or XState stopped returning a subscription object, nothing in this repo would notice until a user reported an empty store and empty `stateDiffs`. `store-adapters.live.test.ts` imports jotai, valtio, xstate, mobx and `@tanstack/query-core` as devDependencies (none reaches shipped code) and asserts the two properties Reticle actually depends on: `getState()` reads the live value after a mutation, and `subscribe()` fires so a STATE_CHANGE is emitted. It caught the jotai typing defect below on its first run. (`@reticlehq/browser`)

- **A committed desktop battery — `pnpm test:e2e:desktop`.** v2.3.0 shipped Electron and Tauri support with NO automated coverage of either: the unit gate cannot boot a main process, and the web battery boots three HTTP servers and no desktop runtime, so the only evidence desktop worked was a hand-run "27/27 / 25/27" in the docs with nothing in the repo that reproduced it. Two specs now start a REAL Electron main process and a PACKAGED Tauri binary (`tauri://localhost`, not `tauri dev` — the dev path serves the frontend from an ordinary http origin and exercises none of the opaque-origin handling that is Tauri-specific) and drive them headless, pinning 31 properties across both runtimes: IPC observed as `ipc://<channel>` including the failure, the planted false green reported as a contradiction, `{ ok: false }` actually filtering, capture through the shell, `fullPage` refused rather than downgraded, concurrent captures surviving, no temp file left behind, and — the one that matters most — an Electron renderer with no preload shim DECLARING the blind spot instead of reading clean. Every bug fixed below was found by driving these two apps by hand; none of them was reachable by any existing gate. (`@reticlehq/e2e`, `@reticlehq/electron-smoke`)
- **CI compiles the Rust.** `packages/tauri` is outside every JS gate and had no job at all, so its Windows capture backend had never been compiled by CI — while `publish-crate.yml` stated in a comment that it was "covered by `cargo check --target` in CI". Now it is: `cargo fmt --check` + `clippy -D warnings` natively on Linux, `cargo check --target x86_64-pc-windows-msvc` for the WebView2 path (verified to actually compile that module rather than skip it), and a macOS runner for the WKWebView path, where a missing objc2 feature flag is the kind of thing only a native build catches. (`reticle-tauri`)

- **`reticle hunt <dir>` — the arithmetic behind the core claim.** Detection already existed: `reticle_crawl` drives every reachable control and reports contradictions, and it has twice found real bugs nobody planted (`swallowed-500-login`, and `ui-advanced-request-failed` on a control whose assertion was green). What was missing was the step that turns those into evidence. Point it at a directory of crawl reports — one per already-merged, already-green checkout — and it answers the sentence worth putting in front of someone: _"N of M merged, already-green changes carried a candidate false green."_ No control arm is needed, because those changes SHIPPED, which makes this the cheapest credible proof available and tells you where to power the eventual A/B. Two honesty properties are enforced by test: a checkout that drove ZERO controls is excluded from the denominator rather than counted as clean (the arithmetic equivalent of a green because no test ran), and every flag is reported as a _candidate_ with the checkout named, because a number that skips manual confirmation is exactly the kind of evidence this project exists to distrust. (`@reticlehq/server`)

- **`reticle_verify_change` — "did my change break anything" in one call.** The agent's real question after an edit took four tools it had to know to chain: work out which saved flows the diff invalidates, replay that subset, then separately hunt for contradictions and untouched controls. Every piece existed; nothing composed them, so the loop was only ever run by an agent that already knew the recipe. Give it the files you edited (or `since` for a git ref) and it answers with one `verified` plus `because`. The honesty guard is the design: **no saved flow covering a change is `unknown`, never `yes`** — "nothing ran" and "everything passed" are the same green to anyone reading a boolean, and `cli-verify` already refuses a green pass with no flows, so this applies the same rule on the MCP side. Flows re-run only because their provenance is unknown are disclosed in `because`, so a verdict never reads stronger than the evidence behind it. Delegates the replay to `reticle_flow_verify` rather than reimplementing it, so the MCP and CLI answers cannot drift.

  A green suite is not the end of the check. When every covering flow passes, it then reads the two channels a suite verdict cannot see: whether anything CONTRADICTED during the replay, and which controls the flows never drove. A contradiction forces `verified:"no"` even with a fully green suite — a regression replay is where that hides best, because the flow was recorded when the app worked and still passes while the write underneath it fails. The reply also carries `measured`, so an absent `contradictions` means "none found" ONLY when it says so: with `parallel`, flows run in leased contexts and the events on the resolved session belong to something else, and reporting a clean sweep from the wrong session would be a false green manufactured by the false-green detector. (`@reticlehq/server`)

- **`verified` + `because` — one field to gate on, instead of eight to interpret.** An action result carried `dispatched`, `settled`, `ok`, `grade`, `attribution`, `coverage`, `integrity` and the assertion verdict, with no rule for combining them: driving this surface produced `settled:false, settleReason:"timeout"` on a fill with no way to tell whether that was a bug or noise. Every action now answers `yes` | `no` | `unknown` with one sentence of deciding evidence; the eight dimensions remain beneath it. Two properties are load-bearing. A CONTRADICTION OUTRANKS A PASSING ASSERTION — measured on the bench app, "Fetch with retry" reports `verified:"no"` while `verdict.pass` is true, which is the false green this project exists to catch, inverted at the one field an agent reads. And `unknown` never collapses into `no`: on the same page three controls report `unknown` because the capture was truncated, which tells an agent to look again rather than to go change code. (`@reticlehq/server`, `@reticlehq/core`)

- **Contradictions now arrive WITH the action, not only when asked for.** Cross-channel disagreement is the one finding a human structurally cannot make — they watch one channel, the screen, so a UI that advanced while its write failed looks like success to them and always will. But it only ran inside `reticle_observe`, which meant it was found only when the agent already suspected something and went looking, inverting the whole point: catching what nobody suspected. `reticle_act_and_wait` now carries `contradictions` (omitted when clean, so a healthy action pays nothing). Driving 18 controls of the bench app surfaced `ui-advanced-request-failed` on "Fetch with retry" **with `verdict.pass = true`** — every other signal said the action was fine. (`@reticlehq/server`)

- **Every tool now advertises a concrete example call.** A schema names the FIELDS; it does not say how they compose, and lean profiles keep only the first sentence of a description — so an agent reads "execute one action against a ref" and guesses `{ action, testid }`. That guess is rejected inside the MCP SDK's own validation, BEFORE Reticle's error handling runs, so the reply is a raw zod dump naming no field and showing no correct shape. Two such round trips cost more than the lean snapshot saves, which quietly refunded the whole token advantage. Examples are validated against their own inputSchema by a test, because a wrong example teaches the mistake with authority. (`@reticlehq/server`)
- **`reticle_inspect` is in the DEFAULT tool surface.** Mapping a DOM node to `src/App.tsx:104` is what turns a finding into an edit, and it is the one capability here with no substitute in any other verification tool — but it sat in `standard` while the default is `hybrid`, so an agent had to already know it existed and reach it through `reticle_run`. Observed over a full 43-tool drive: it never gets called. The measured floor that justifies a lean core was about CUTTING to 8 tools, not about holding at 12. (`@reticlehq/server`)
- **`reticle_coverage` — which controls you drove, and which you never touched.** Every other read answers a question the agent already thought to ask, which bounds verification by the agent's imagination. This answers the one question that says whether to STOP: `{ total, exercised, untouched:[{ref,label}] }`. Driven refs are recorded at the single command chokepoint, so `act_sequence` and flow replay count too, and they survive event-buffer eviction — otherwise "untouched" silently degrades into "recently untouched", which reads as thorough while meaning the opposite. Unadvertised (zero per-turn cost), reachable via `reticle_run`. (`@reticlehq/server`)
- **`reticle_affected` — which saved flows a diff invalidates.** The logic existed as a CLI command, deliberately kept off the MCP surface because an advertised tool costs tokens every turn. That reasoning is right and is preserved (it is unadvertised, reached through `reticle_run`); what it missed is that the AGENT holds the diff and an MCP client may have no shell, so the party with the question could not reach the party with the index. (`@reticlehq/server`)

- **`{ kind: 'net', ok: false }` — assert on the OUTCOME, not on a status Reticle invented.** IPC has no status code; the 200/500 Reticle derives exists so the existing filters keep working, but making an agent write `status: 500` meant asserting on Reticle's own encoding rather than on the app's behaviour. `ok` is now a first-class net predicate: authoritative when the observer set it (IPC always does), falling back to the HTTP status so ordinary web requests need no change. (#64) (`@reticlehq/server`)

- **`@reticlehq/electron` — desktop is now a first-class adapter, not files bolted onto the SDK.** The preload and main-process helpers were shipping as loose `.cjs` files inside `@reticlehq/browser`, which made desktop the only integration that was not a peer of `@reticlehq/react` and `@reticlehq/next`. They now live in their own package with `./preload` and `./main` entry points. Follows the repo's existing convention for a plain-CommonJS package (as `@reticlehq/next` does): no TypeScript gate scripts, and excluded from the ESLint config, because an Electron preload MUST be CJS — a sandboxed one cannot load ESM at all — so `no-require-imports` cannot apply to it. (#64) (`@reticlehq/electron`, `@reticlehq/browser`)
- **The desktop string contract is generated, so drift is impossible rather than merely tested.** Three strings (`__reticleIpc`, the capture channel, the capture-file prefix) were hand-copied across six files that cannot import each other — a CJS preload cannot load the ESM SDK, and the daemon shares no module graph with the renderer. They now have exactly one definition, in `@reticlehq/core`, and `scripts/gen-desktop-contract.mjs` emits `dist/desktop-contract.cjs` from it at build time — the same generate-from-source pattern core already uses for the wire JSON Schemas. The previous drift-guard test is replaced by tests that the generator is complete and the built output is current. (#64) (`@reticlehq/core`)

- **Electron and Tauri support.** A desktop app now connects to the bridge like any other app — you start it exactly as you always do (`npm run dev`, `electron .`, `cargo tauri dev`) and it dials out; there is no URL to open and no browser involved. Snapshot, query, act, observe, network, console, state, assert, flows, screenshots and visual diffs all work, headful or headless, on both runtimes — a 43-tool drive scores identically on each. See [`docs/desktop-apps.md`](docs/desktop-apps.md). (#64) (`@reticlehq/browser`, `@reticlehq/core`, `@reticlehq/server`)
- **IPC observer — a desktop app's backend calls are no longer a blind spot.** Electron and Tauri reach their backends over IPC, which `fetch`/`XHR` patching cannot see; every such call was invisible, so `reticle_network` reported nothing, `act_and_wait` had no in-flight request to settle on, and `assert { net }` was vacuously true — a false green by construction. IPC calls are now recorded as ordinary requests (`ipc://<channel>`, `initiator: "ipc"`), with a synthetic 200/500 status so the existing filters and net predicates keep working, plus `ok` and the error message the main process or Rust command actually returned. Neither runtime's IPC entry point can be monkey-patched from the page — Tauri defines `__TAURI_INTERNALS__.invoke` as `writable:false, configurable:false` and Electron's `contextBridge` object is deeply frozen — so each uses the seam that exists: a Tauri `invoke` already travels as a `fetch` to its `ipc://` protocol and is picked up there, including a translation of the `Tauri-Response` header (the transport answers HTTP 200 even when the Rust command returned `Err`, so an untranslated failure read as a success); Electron needs one line at the top of the preload, `require('@reticlehq/electron/preload')`. (#64) (`@reticlehq/browser`, `@reticlehq/core`)

- **Screenshots on Electron, via `@reticlehq/electron/main`.** One line in the main process (`installReticleCapture(win)`) makes `reticle_screenshot` and `reticle_visual_diff` work on a desktop app — no CDP flag, no extra packages, works on a packaged `file://` renderer. It uses `webContents.capturePage()`, which reads the window's own backing store. Capturing a screen region was built and then deliberately deleted: it photographs whatever is on top, so an app window behind the editor would have been saved as a visual baseline showing the editor — the exact false green Reticle exists to eliminate. Tauri gets the same capability from `reticle-tauri` — see below. (#64) (`@reticlehq/browser`, `@reticlehq/core`, `@reticlehq/server`)

- **Failure acknowledgement no longer depends on reading English.** The contradiction hunter decided whether an app had surfaced a failure by pattern-matching English words in its state, so a German or Japanese app that reported the failure perfectly well would have been accused of hiding it. It now checks a structural signal first: whether the app echoed the failed call's OWN error text into its state — evidence in any language that it knows the call failed. The lexical patterns remain as a fallback, and are documented as the soft edge they are. (`@reticlehq/server`)
- **`failure-misattributed` — the server broke and the app blamed the user.** A 5xx answered with "invalid credentials" / "not permitted" sends someone to fix something they cannot fix, while the real fault goes unreported. Found by pointing the hunter at a bug this work did not write (bench-app's `swallowed-500-login`, which forces `/api/login` to 500 while the app answers `auth:denied`). A 4xx is excluded: there, blaming the client is correct. (`@reticlehq/server`, `@reticlehq/core`)
- **A fast-gate guard for the desktop contract.** The desktop wiring is three strings hand-copied across five files that cannot import each other (a sandboxed CJS preload cannot load the ESM SDK; the daemon shares no module graph with the renderer). A rename in any one of them broke desktop silently while every test still passed — the same drift class that once left four e2e specs dead across a framework. The guard reads the files as text, asserts they still agree, and costs milliseconds. (`@reticlehq/server`)
- **The contradiction hunter — cross-channel disagreement, reported as a finding.** Every other check in Reticle reads ONE channel and asks "did something bad happen there?" (a console error, a 500, a control that did nothing) — a human can do that too, just slower. This asks a question a human structurally cannot: do the channels DISAGREE? A person watching an app has one channel open, the screen, so a UI that advanced while its write failed looks like success to them and always will. Five kinds ship, each a false green that passes CI today: `ui-advanced-request-failed`, `signal-contradicted` (the app fired its own success signal over a failed request), `response-ignored` (a write succeeded and nothing on the client moved), `duplicate-request` (double-submit), and `request-never-settled` (the UI moved on over an in-flight call, which is what makes a later `settled` assertion a false green). Surfaced in `reticle_observe` (omitted entirely when clean, so a healthy action costs zero tokens) and per-control in `reticle_crawl`, which makes an autonomous crawl of an unknown app a false-green hunt rather than an error-log scrape. Rules are narrowed to avoid crying wolf: the write-shaped ones ignore GETs, and the headline rule stays silent when the app recorded the failure in its own state — otherwise correct code that catches a rejection and renders "could not add" would be reported alongside code that swallowed it. (`@reticlehq/server`, `@reticlehq/core`)

- **`reticle doctor` now diagnoses desktop misconfiguration.** Every failure it catches is SILENT, which is why it exists: a Tauri app whose CSP does not allow the bridge WebSocket runs perfectly and simply never appears in `reticle status`, and an Electron app missing the preload line reports zero network activity forever — which reads as "this app makes no backend calls" rather than "you are blind to all of them". It checks the Tauri CSP against the port actually in use (not a hardcoded default), warns when a custom CSP dropped the `ipc:` source Tauri needs for `invoke` itself, and checks that an Electron preload requires the shim and the main process installs the capture helper. Each finding names the file, the consequence, and a copy-pasteable fix. A healthy desktop project gets an explicit ✓ rather than silence, because silence reads as "not checked". (#64) (`@reticlehq/server`)
- **One-line desktop setup: `reticle({ desktop: true })` in the Vite plugin.** A desktop renderer now wires up exactly like a web app instead of hand-writing `reticle.connect()`. The flag changes two things a web app must never get: the plugin also applies to `vite build` (a packaged renderer is a production build with no dev server, so the default `apply: 'serve'` dropped the plugin and shipped an app with no connect at all), and `connect()` gets `allowInProduction` because that renderer reports NODE_ENV=production. Web behaviour is untouched and covered by tests asserting no desktop keys leak into a normal connect. (#64) (`@reticlehq/vite-plugin`)

- **`{ fullPage: true }` on a desktop app is honoured where possible and REFUSED where not — never silently downgraded.** It used to fall through to the shell, which photographs the viewport, so a caller asking for the whole scroll height got an image without the content below the fold and banked it as a full-page baseline; every later diff of that baseline was green about a region it had never captured. Tauri on Linux now does a real full-document capture (WebKitGTK renders it offscreen — measured under `xvfb`: 800x400 viewport vs 800x2400 full page from the same window). macOS, Windows and Electron cannot, so they answer `full-page-unsupported` and write no baseline at all. (#64) (`reticle-tauri`, `@reticlehq/browser`, `@reticlehq/electron`, `@reticlehq/core`, `@reticlehq/server`)

- **`reticle-tauri` — screenshots and headless mode for a Tauri app.** Two lines in `main.rs` and nothing on the JavaScript side: `reticle_capture` calls `WKWebView.takeSnapshot`, and `on_page_load` hides the window under `RETICLE_HEADLESS=1`. Capture renders the webview rather than the screen, so — like Electron's `capturePage()` — it needs no screen-recording permission, cannot return another window's pixels, and is correct with nothing on screen. The SDK invokes the command through Tauri's own internals, because Tauri has no preload stage where a shim could be installed; an app with its own capture can still expose `window.__reticleIpc.capture()` and the SDK prefers it. Capture is implemented on all three desktop platforms, each through its own webview API — `WKWebView.takeSnapshot` (macOS), WebView2 `CapturePreview` (Windows), and `webkit_web_view_get_snapshot` (Linux/BSD) — all capturing the visible viewport so a baseline taken on one platform is comparable on another. The Windows and Linux paths are type-checked against their real targets (Linux natively in a container, since its build scripts cannot cross-compile) but have not been run on those platforms. (#64) (`reticle-tauri`, `@reticlehq/browser`, `@reticlehq/core`)

- **A command timeout now says what to DO about it.** `command 'snapshot' timed out after 8000ms` is eight seconds of silence followed by a fact with no cause, and on macOS the likeliest cause for a Tauri app is not a bug in the app at all — an occluded window, or one on another Space, has its WKWebView suspended by the OS. The message now adds that diagnosis and the fix (bring the window onto the active Space; `xvfb-run` on Linux CI). The advice is added, never substituted, and only for a runtime that can actually suffer it: Electron is immune, and blaming occlusion there would send someone to move a window that was never the problem. The SDK reports its runtime with PAGE_HEALTH, because a URL cannot tell a Tauri dev server from a plain localhost app. (#64) (`@reticlehq/server`, `@reticlehq/browser`)

### Fixed

- **A structural blind spot no longer destroys the verdict it should merely qualify.** Every blind spot fed `integrity.issues`, and an unclean capture forces UNKNOWN — so the moment virtualization became detectable, every verdict on every data grid became UNKNOWN, permanently. A tool that answers "unknown" to everything is as useless as one that answers "yes" to everything, and it is the same failure: a verdict that does not depend on the evidence. Blind spots now split by what they actually mean. **Impeaching** (events were DROPPED, so the window is a sample and any negative may be false) stays an integrity failure — today that is `rate-limited` alone. **Bounding** (a cross-origin frame, a closed shadow root, 9,970 virtualized rows that were never rendered) is reported as `coverage: partial` and leaves the verdict intact, because what was observed was observed correctly; there is simply a boundary, and it is usually permanent. Verified on a 10,000-row console: the assert passes and carries `partial — 21 virtualized unmounted rows unobserved`, rather than refusing to answer. (`@reticlehq/server`)

- **A `202 Accepted` was counted as success, so every asynchronous workflow was verifiable at the moment nothing had been decided.** 202 is the one status in HTTP whose meaning is "the server took this and has NOT finished" — folding it into the 2xx band made an optimistic UI, a settled page and a green verdict all agree while the outcome did not exist yet. Measured on a logistics console with server-side reconciliation: a dispatch answered 202, the row rendered `dispatched`, the page settled, `verified: "yes"` — and the server REVERTED the shipment to `held` 1.2 s later. Now UNKNOWN, with the reason and what to do: re-check once it reconciles. Deliberately UNKNOWN rather than NO — nothing has failed, and reporting a failure that has not happened is the same error inverted. (`@reticlehq/server`, `@reticlehq/core`)
- **`VIRTUALIZED_UNMOUNTED` had a label on the server and nothing ever emitted it** — a declared blind spot that could not fire, shaped like the most common data-heavy UI there is. On a 10,000-row grid, 29 rows were in the DOM and a verdict reported FULL coverage: "no shipment is held" was a claim about 29 rows delivered as a claim about all of them. Detection measures EMPTY RESERVED SPACE (the area a scroller has sized for and left unfilled) rather than guessing from child counts, so an ordinary long list — even one with large gaps between rows — measures zero and never reports. Verified on two live apps: the virtualized console now says `partial — 21 virtualized unmounted rows unobserved`, and a plain 800-row table still says full. (`@reticlehq/browser`)
- **The streamed-body watcher was gated on a content-type allowlist containing `x-component`** — which is to say "Next.js RSC, plus two guesses". It closed the one defect it was written against and left every other streamed response as invisible as before: a chunked `application/json` from a token API, a streamed HTML document, a server-assembled export. Detection is now structural — a response with a body and no `content-length` is being sent chunked, which is the wire's own way of saying the server is still writing — with `text/event-stream` excluded because a stream that is supposed to stay open should not hold `settled` for its full bound. (`@reticlehq/browser`)
- **The stream watcher threw unhandled rejections wherever `Response.body` is absent.** The guard checked `=== null`, but jsdom has no `body` at all — so `.getReader()` threw out of a detached promise, from code the host never called. An observability layer must not do that. Duck-typed now. (`@reticlehq/browser`)

- **A text change was invisible — the most common thing an app does, unobserved.** `characterData` fires only when an EXISTING text node's `data` is edited in place. Every ordinary way of setting text — `textContent`, `innerText`, appending a text node, a framework replacing a child — REPLACES the node instead, arriving as a childList mutation carrying a `Text` node, and both childList loops skipped those with `if (!(node instanceof Element)) continue`. Measured on a live page: `firstChild.data = x` emitted `dom.text`; `textContent`, `innerText` and `appendChild(createTextNode())` emitted NOTHING. So a grid cell going "pending" → "approved" produced no event at all, `reticle_observe` answered `domChanged: 0` over a screen that had visibly changed, `settled` went quiet instantly (quiet being exactly what it tests for), and a `not`-style assertion over the DOM channel would have passed on a page that did change. Text nodes are now handled in the childList path, whitespace-only reshuffling excluded so a re-indenting re-render does not flood the timeline. Cost check on the hot path: the refund flow is byte-for-byte unchanged (4 calls / 4,973 bytes) because `act_and_wait` returns a bounded summary — only an unfiltered `reticle_observe` grows, and that call already carries a cost hint recommending filters. (`@reticlehq/browser`)
- **The DOM observer referenced the global `Node` constructor**, which is not guaranteed to exist wherever the SDK runs — it threw a `ReferenceError` rather than degrading. Uses the numeric nodeType instead. (`@reticlehq/browser`)

- **`jotaiStore` did not compile against a real Jotai store.** The adapter typed its parameter as `atom: object`, and Jotai's `get` is `<Value>(atom: Atom<Value>) => Value` — a function that REQUIRES an `Atom` cannot stand in for one that accepts any `object`, so `jotaiStore(createStore(), { … })` was a type error. Advertised in the README, shipped, and unusable from TypeScript without a cast. It is now generic in the atom type. Found by importing the actual package: four of the five store adapters (`jotai`, `xstate`, `valtio`, `mobx`) were wired by no app anywhere and had never once run against the library whose shape they assume. (`@reticlehq/browser`)

- **`settled` was a false green on every streaming Suspense boundary.** `fetch` resolves at HEADERS, so a response whose body is still arriving was recorded complete — and quiet is exactly what `settled` tests for. Measured on a Next.js App Router page: the RSC payload's NET_REQUEST landed 16 ms in, the shell and a `loading rows…` fallback rendered at 3013 ms, and the boundary's real content arrived at 3902 ms. The 889 ms in between produced NO events at all, so `act_and_wait { until: settled }` returned `verified: "yes"` with the fallback still on screen and zero rows rendered. On Next that is the DEFAULT rendering path, so it was a green on every streamed navigation. A streamed response body is now watched to its end (`NET_STREAM` open/close, `transport: "fetch"`) and `evalSettled` counts an unclosed body as in flight, the same as a request with no completion. Verified on the live app: settle now returns after the rows exist. (`@reticlehq/browser`, `@reticlehq/core`, `@reticlehq/server`)
- **The watch is bounded, and the bound is a TIMER for a reason.** An endless stream must not hold `settled` open forever, and a deadline checked after each read never fires on an IDLE stream — the reader parks inside `read()` waiting for a chunk that never comes. Racing the read against a timer fixes that; proven against an ndjson endpoint that flushes one chunk and then says nothing, where settle now completes at the 10 s bound instead of hanging. `text/event-stream` is deliberately NOT watched: an SSE stream is _supposed_ to stay open, so watching it would make every first settle pay the full bound for a stream doing its job — real SSE is covered by the EventSource observer. Streams outside the allowlist remain unobserved: the gap is narrowed, not closed, and saying so beats implying otherwise. (`@reticlehq/browser`)
- **`bodiesNotCaptured` gave Vite-specific advice to a Next.js app.** Driving a server action returned remediation naming `vite.config` — a file a Next user does not have. Remediation that does not apply to the reader's stack is worse than none. Now framework-neutral, leading with `reticle.connect({ captureNetworkBodies: true })`. (`@reticlehq/server`)

Five of these were found by DRIVING a real 128-row Razorpay merchant dashboard (23 authored defects, written ground truth) rather than a fixture. That distinction is the point: the demo apps in `apps/` plant bugs shaped like the detector — a handler that ALWAYS throws produces a guaranteed failed request in the window — so they cannot expose a transient, a cardinality error, or a payload that never reaches a tool. Every item below is a verdict Reticle got WRONG on an app it did not author.

- **`reticle_network { count: N }` silently meant "at least N".** `waitForPredicate` resolves the instant a check passes, so a count — which only rises while a window is open — was concluded from a sample. Live: a Refund confirm fired two POSTs 59 ms apart and `until: { count: 1 }` returned `pass: true, matched: 1`. `evalNet` was counting correctly; the wait had stopped looking. Exact-count predicates now HOLD after first reading true, re-evaluate, and fail if an N+1th arrived — 2-in-59 ms now fails with `observed: "2 matching network call(s)"`, and an honest single still returns in ~330 ms rather than burning the timeout. The ceiling is stated rather than hidden: a duplicate arriving after the 300 ms hold still passes, so this converts an unbounded false green into a bounded one. (`@reticlehq/server`)
- **A click that did NOTHING was reported `verified: "yes"`.** `until: { kind: 'settled' }` is satisfied by a page that is quiet, and a page that did nothing is quiet — so a click landing on a non-interactive wrapper (which `reticle_query { by: 'text' }` will happily resolve instead of the button beside it) produced zero DOM, zero network, zero state, zero signals, and a green verdict reading "no channel disagreeing". No channel disagreed because nothing happened. Two fixes: the Electron helper now writes the PNG to a temp file and returns its PATH (the daemon and the app always share a machine — the bridge is loopback — so nothing large needs to cross the event wire, and the path is validated to be inside the OS temp dir with Reticle's own prefix so the daemon cannot be pointed at an arbitrary file); and the server verifies a capture ends with `IEND` before saving, so an incomplete image fails loudly instead of banking a corrupt baseline a later diff will trust. A real capture is now ~324KB where the truncated one was 49KB. (#64) (`@reticlehq/browser`, `@reticlehq/server`)

- **`{ kind: 'route', contains }` now matches the whole route, not just the pathname.** A hash router keeps the entire route in the fragment, so `pathname` never moves — which made a `contains` route assertion permanently unsatisfiable for every HashRouter app. That is not a niche case: HashRouter is the standard router for a packaged Electron/Tauri renderer, because on `file://` an absolute `pushState` rewrites the URL to a file that does not exist. `contains` now matches `pathname + search + hash`; exact `pathname` matching is unchanged. (#64) (`@reticlehq/server`)
- **The bridge no longer crashes on a desktop webview's Origin.** A WebSocket handshake carrying an opaque origin — `tauri://localhost`, `app://.`, `file://` — reached `new URL('null')` inside the `verifyClient` handler and threw, an uncaught exception in the HTTP upgrade path. Opaque origins are now kept verbatim (so they can be allow-listed at all, which normalization previously made impossible) and, carrying no attributable host, are gated on the pairing token exactly as a missing `Origin` already was. (#64) (`@reticlehq/server`)
- **The SDK no longer refuses to start inside a desktop app.** The localhost gate exists to stop a remote website driving a developer's local bridge, but it read a `file://`, `tauri://` or `http://tauri.localhost` page as remote and blocked the connection outright. A local desktop webview is now recognized as local; a remote page reaching a loopback bridge is still blocked, and a remote _bridge_ still requires the explicit opt-in plus a token. (#64) (`@reticlehq/browser`, `@reticlehq/core`)
- **`reticle open` explains itself on desktop.** With no app connected it suggested passing a URL, which does not exist for an Electron or Tauri app; it now says to start the app normally and let it connect. Its reuse check also no longer treats two different desktop apps as the same app — both opaque origins compared equal. (#64) (`@reticlehq/server`)
- **`withFileLock` reclaims a path's chain entry once it settles,** guarded by pointer identity so a queued successor is never dropped — previously every unique file path locked in a long-running daemon occupied a Map slot forever. Thanks @DevChiniwala. (#63) (`@reticlehq/server`)
- **A bridge outage no longer opens a silent hole in the ledger.** When the SDK's offline queue filled during an outage it discarded its oldest events and told no one: `TRANSPORT_OVERFLOW` was defined in the contract and consumed by the server's segment rollup, but nothing ever emitted it, so the hook had been dead in every release. The gap then read as "the app did nothing" — and because the segment was never marked truncated, its understated counts were folded into the learned deviation envelope in `.reticle/envelopes.json`, so one blip could quietly raise the bar a later regression is judged against. The transport now declares each gap exactly once on reconnect, ahead of the replayed backlog, carrying the seq/`t` of the last event it displaced so the marker sorts at the hole instead of at the end of the session. Thanks @hardikguptaofficialgit. (#66) (`@reticlehq/browser`)
- **A failed suite could produce a JUnit report that CI read as zero tests.** `escapeXml` covered the five XML entities but not the characters XML 1.0 forbids outright (§2.2), so a single ANSI colour code in a failure message — routine in error output — wrote a raw `U+001B` into the document and no parser would accept it. Most CI ingesters answer an unparseable report by reporting no tests at all, which renders as an empty or passing step: the one artifact whose whole job is carrying bad news dropped it. Illegal control characters are now stripped before escaping, and the full failure text moved into the `<failure>` element's content where newlines survive — the `message` attribute keeps the first line as a summary, because XML attribute-value normalisation (§3.3.3) flattens a multi-line message into one run-on line. Thanks @DevChiniwala. (#80) (`@reticlehq/test`)
- **A scoped state read no longer contradicts the unscoped one.** `capDepth` and `selectPath` run on RAW store values, ahead of the serializer that deliberately handles `Date`, `Map` and `Set` — and knew about none of them, so anything narrowed with `path` or `depth` collapsed a `Map` or `Set` to `{}` and a `Date` to an empty object. That is the false green the serializer's own Map branch exists to prevent, reintroduced one function upstream: an agent that narrowed a read to keep it cheap was told a populated collection was empty, with no truncation marker, because nothing had been truncated — the value was thrown away by a shape check. `capDepth` now treats a `Date` as a leaf and renders `Map`/`Set` with honest size markers at the budget, and `selectPath` walks into a `Map` and reports its keys on a near miss. Thanks @DevChiniwala. (#83) (`@reticlehq/core`)
- **`redactUrl` no longer rewrites a query string it did not redact.** The query was always round-tripped through `URLSearchParams`, and the rebuilt string was emitted whenever ANY part of the URL changed — so a path-embedded token being redacted silently re-encoded an untouched query (`?next=/a%20b` became `?next=%2Fa+b`, `?debug` gained an `=`). Since `urlContains` is how an agent asserts on a request, that failed a predicate written against the URL the app actually sent, with no cause the agent could see. The query is now rebuilt only when a query key genuinely matched. Thanks @DevChiniwala. (#79) (`@reticlehq/browser`)
- **`registerStore` no longer accepts a store it can never read.** A source with `subscribe` but no `getState` — the shape of a Svelte store, and an easy mistake with any library — failed the `{getState, subscribe}` duck-type and was then stored as if it were a bare getter function. It appeared in `storeNames()`, so `reticle_state` advertised it, and every read came back `{ __error: 'getter is not a function' }`; worse, the warning meant to unstick the developer said the store was "registered without a subscribe function" — naming the one thing the object did have, and pointing away from the missing `getState`. Such a source is now rejected with a message that names the real gap. Thanks @DevChiniwala. (#82) (`@reticlehq/browser`)
- **`spawnDaemon` is injectable, and its fd-leak regression guard is no longer a false green.** The test that claimed to prove the parent closes its copy of the log fd asserted only that a later `writeFileSync(log, …, {flag:'a'})` succeeded — which it does whether or not the fd was closed, so the guard passed against the bug it was written to catch. `spawnDaemon` now takes an optional deps object (`home`, `openFile`, `closeFile`, `spawnChild`, `pidAlive`) defaulting to the real implementations, the same seam pattern `reclaimStaleDaemons(home, pidAlive)` already used, so every cleanup path is asserted directly against spies in a temp dir — no real process spawned and no real `~/.reticle` touched. Existing call sites are unchanged. Thanks @DevChiniwala. (#78) (`@reticlehq/server`)

### Security

- **A presigned S3/GCS URL was recorded verbatim.** A presigned URL is a bearer credential — anyone holding the string can read the object until it expires — and its parameters are named in a way the sensitive-key rule did not cover: `X-Amz-Signature`, `X-Amz-Credential` (which carries the AKIA access key id) and `X-Goog-Signature` all passed through unredacted, so they reached the agent transcript, the session journal under `.reticle/`, and any recorded flow, which is a file users commit. Bare `signature`/`sig`/`credential` keys were likewise missed. The rule now covers them, boundary-anchored so ordinary app fields (`signatureVersion`, `credentialScope`, `signatureUrl`) stay visible, and the non-secret parameters an agent needs for context (`X-Amz-Algorithm`, `X-Amz-Date`, `X-Amz-Expires`, `X-Amz-SignedHeaders`) are deliberately preserved. This closes a gap left by the earlier query-credential fix rather than a regression of it. Thanks @DevChiniwala. (#81) (`@reticlehq/core`)

The single-install `@reticlehq/core` umbrella is retired in favour of **audience-scoped packages**. ### Breaking Changes

- **The `@reticlehq/core` umbrella is split into scoped packages.** In v1 you installed one package and imported everything from it via `/server`, `/vite`, `/next`, … subpaths. In v2 you install the package for your role:

  | `@reticlehq/core` (the dev SDK + React adapter)  | `@reticlehq/react`         |
  | `@reticlehq/core/vite`                           | `@reticlehq/vite-plugin`   |

## [0.7.0] — 2026-06-20

The regression-testing release. Reticle's flow `success` is now a **declared, deterministic, post-settle consequence** over program truth — not just "the element is there" — and the same flow replays with no LLM, so a CI gate diffs the verdict exactly (0% flake) at a fraction of the tokens an LLM re-drive costs.

### Added

- **`state` predicate — assert store truth** (`packages/server`, `packages/protocol`). Assert a value inside a registered store the DOM never showed: `{ kind: "state", store?, path, equals? }`, with `equals` a literal or a `{ $gte | $contains | $length }` operator. Available in `reticle_assert`, `reticle_act_and_wait`, as a per-step `assert-state` invariant, and as a flow `success-state` golden end-condition. Catches a UI-vs-store **desync** and a dead-handler **green-but-wrong** regression that no DOM read can — the success oracle fails when the store didn't change, with no testid drift.
- **Flow consequence family — `net { count }`, `console { absent }`, `state { hold }`** (`packages/server`, `packages/protocol`). A flow's `success` (via `reticle_annotate success-state`) now compiles to a real predicate over more than presence: `net { count }` asserts a request fired EXACTLY N times (catches a **double-submit** / retry-storm a presence check passes); `console { absent }` asserts the action left a **clean console** (catches a silent `console.error`); `state { hold }` asserts an unrelated store path **did not move** (catches an action's unintended **blast-radius** side-effect). Cardinality/absence/invariant predicates are read **post-settle** so a wait-until-true check can't pass before the regression lands.
- **Design-token awareness in `reticle_inspect`** (`packages/server`, `packages/browser`). Inspect now reports theme compliance — `{ colorToken, backgroundToken, offTheme, tokenCount }` — so an off-palette color (a value no design token defines) is observable in one call, not just "a color rendered."

- **On-demand tool loading — `dynamic` / `hybrid` MCP profiles** (`packages/server`). Load tool schemas as needed instead of paying for the full set up front, cutting the agent's per-turn token floor.
- **Richer observation** (`packages/browser`, `packages/server`): a `net.pending` signal for in-flight / hung requests; generic-container text in the snapshot so a silent DOM removal is visible; a grid layout signature so a CLS/layout regression shows up.

### Changed

- **Leaner agent verify loop** (`packages/server`). Terser tool descriptions and compact `reticle_network` / `reticle_console` projections on the lean profiles roughly halve the per-turn token cost; `core` is the default profile tuned for the build-verify loop.

The tool's `outputSchema` declared `{ ok, match, diffPct }` but the handler returned the diff engine's real shape (`{ matched, changedPixels, ratio, … }`) and never set `ok`, so every real diff failed MCP output validation. - **`reticle mcp --drive <url>` / `reticle serve --drive <url>`** — pass a URL and Reticle launches its own Playwright browser at that URL, giving the agent full autonomous control without relying on the user's open browser tab.
- **`reticle mcp --headed` / `--headed` flag** — opt in to a visible browser window so you can watch exactly what the agent is doing.
- **Three new update MCP tools** (`packages/server`):
  - `reticle_version_info` — returns the installed version, execution kind (npx / global / local), and whether a newer version is available on npm.
  - `reticle_apply_update` — upgrades Reticle in place; requires `confirm: true` to actually run.
  - `reticle_rollback` — downgrades to the previous version; requires `confirm: true`.
- **Presenter mode** (`packages/browser`, `packages/server`) — `reticle.connect({ present: true })` mounts a dev-only HUD overlay that the agent can control: `reticle_narrate` shows a caption, `reticle_highlight` draws a ring around any element. The HUD is excluded from snapshots and tree-shaken in production.
- **Unified `SKILL.md` at repo root** — a single skill file auto-detects mode: setup wizard on first run (no `.reticle.json`), live-app testing on every run after. Covers Claude Code, OpenCode, Codex CLI, Cursor, Windsurf, VS Code, and Zed MCP config formats.
- **`.reticle.json` project config** — written after first-run setup; persists `port`, `headed`, `framework`, and `harnesses` so subsequent runs need zero questions.
- **`dev:reticle` script** in `apps/demo` — second Vite dev server on port 4310, isolated from the user's normal dev port.

### Fixed

- **All-throttled session auto-selection** (`packages/server`). When every connected tab is hidden (e.g. user is in VS Code with Chrome on another desktop), `SessionManager.resolve()` now picks the session with the freshest heartbeat instead of throwing `"multiple sessions connected"`.
- **Presenter HUD shows on bridge connect** — the overlay now mounts as soon as the SDK connects to the bridge, not only after the first `reticle_narrate` call.
- **`reticle_narrate` MCP schema validation** — relaxed the output schema so the tool no longer rejects responses from narration calls.
- **`reticle_inspect` / `reticle_clock` output schemas** — relaxed to pass through extra fields instead of stripping them, fixing spurious validation errors.

## [0.4.0] — 2026-06-11

First public release. Reticle is the **proof layer for AI agents** — it verifies your running web app from the inside and returns a **verdict with evidence** instead of a screenshot.

### Added

- **The verify loop over MCP** — `look → act → observe → assert`. `reticle_assert` evaluates a structured predicate against the live app and returns `{ pass, evidence, failureReason? }`, typically in ~100 tokens.
- **Six reaction types in one assert** — network calls, DOM changes, SPA navigation, console & errors (including "no errors during this flow"), animations, and app **signals**.
- **App signals** — `reticle.signal()` lets your app emit the facts a screenshot can't see (the store committed, the webhook arrived); a bundled ESLint rule flags mutations that forgot to emit one.
- **Regression detection** — `reticle_baseline_save` + `reticle_diff` to catch silently removed elements or new console errors before they ship.
- **Source mapping** — DOM element → React component → `file:line`, on React 18/19 and Next.js (keeps SWC).
- **Autonomous crawler** (`reticle_crawl`) that clicks every reachable control and classifies what breaks.
- **Declarative spec runner** (`@reticlehq/core/test`) for signal-bound, headless verification specs.
- **The `reticle` CLI** — bridge + MCP server, plus `reticle drive` for a launched browser.
- **Single package, subpaths** — `@reticlehq/core` ships the browser SDK (`.`), the server (`./server`), the spec runner (`./test`), source mapping (`./next`, `./babel`), and the lint rule (`./eslint`) — one install.

### Notes

- **Dev-only and localhost-only by default**; observers are additive and reversible, and the SDK is tree-shaken out of production. No telemetry.
- **Token efficiency** — a full verify loop is ~100 tokens vs ~7,300 for a full-tree snapshot (~73× on the common loop; ~1.8× full-tree-vs-full-tree). See [`docs/token-efficiency.md`](docs/token-efficiency.md) for the methodology and honest caveats.
